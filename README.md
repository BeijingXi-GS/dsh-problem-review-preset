# 命题质量审核员（DSH Agent 预设 · problem-review）

> 一句话定位：给一道信息学竞赛题（CSP-J/S、NOIP、GESP、洛谷、AtCoder、Codeforces），
> 按 **D1 重复程度 / D2 思维深度 / D3 知识叠加程度** 三个维度打出带证据的 0–5 分，
> 输出可直接执行的「保留 / 改造 / 淘汰」结论——不是「感觉这题不错」，而是每个分数都能对回题面原句。

> English abstract: A DeepSeek Harness agent preset for auditing competitive-programming
> problems. It scores any problem on three dimensions — novelty/repetition (D1), reasoning
> depth (D2, a weighted mix of reasoning-chain length, causal analysis, abstraction and
> transfer), and knowledge stacking (D3) — and returns a scored card with fingerprints,
> duplicate-search candidates, feasible solution routes, per-dimension evidence, misjudgement
> risks and a keep / rework / discard verdict. Install it as a DSH bundle and select
> 「命题质量审核员」 in a new session.

## 解决什么问题

| 你的痛点 | 它给什么 |
|---|---|
| 「这题是不是换皮题？」 | D1 指纹（解法路径 / 关键转化 / 数据结构 / 约束形态）+ 查重候选 + 同构度与差异点，判到证据层 |
| 「题目难在哪，说不清」 | D2 四项加权（R 推理链 / C 因果 / A 抽象 / T 迁移）+ 题眼只计一次，分数对得回题面原句 |
| 「一套题里互相重复，看不出来」 | 集合内查重：把这一批题的指纹两两比对，按解法路径 + 关键转化聚成重复簇 |
| 「分层作业不知道哪题放哪层」 | D3 叠加结构（单点/串联/并联/嵌套）+ 教学复用价值 → 保留 / 改造 / 淘汰 + 分层建议 |
| 「几个人评出来的分数对不上」 | 锚点表 + 校准流程 + 每维置信度与依赖假设，先对齐再批量 |

## 它评什么

| 维度 | 子项 | 分值 |
|---|---|---|
| **D1 重复程度** | 骨架 / 解法路径 / 数据约束形态（「关键转化」只进指纹与查重，不计分），附「教学复用价值」 | 0–5，越高越重复 |
| **D2 思维深度** | 推理链长度 R 0.30、因果分析 C 0.25、抽象能力 A 0.25、迁移能力 T 0.20（权重可调但要写明） | 0–5，保留一位小数 |
| **D3 知识叠加程度** | 知识点清单 / 叠加结构（单点·串联·并联·嵌套）/ 耦合强度（强耦合 vs 拼装） | 0–5，取整数 |

三个维度的口径要点：

- **D1 锚点**：0 = 找不到同构题；2 = 主链路相似但关键转化或约束有一处是新的；
  4 = 与某道已知题几乎一比一对应；5 = 换皮题（只改背景文字，解法与坑点完全相同）。
  查重先抽「解法路径 / 关键转化 / 数据结构 / 约束形态」四项指纹，再写「同构度 + 差异点」。
- **D2 合成**：R 很高但 C/A/T 都很低 = 「长但不深」的机械长链，必须在评语里点破。
- **D3 锚点**：2 = 一主一辅；3 = 两个知识点强耦合；5 = 三层以上嵌套或需自定义数据结构承载。
  叠加高而推理浅的题是「大杂烩」，不应当难题推荐。

**计分归属（防重复计分）**：先找出本题的「题眼」——决定解法成立的那一个观察/转化。
题眼**只计一次**：偏正确性论证计入 C，偏建模/抽象计入 A，偏跨方法组合计入 T；
同一洞察最多在另一个维度作为引用依据出现，不再加分。

**集合内重复（批量审核必做）**：除对外查重，还要把这一批题的指纹两两比对，
按「解法路径 + 关键转化」聚类成重复簇，回答「我这一套题里有多少是彼此重复的」。

## 三条硬约束（写在 persona 里）

1. **证据优先**：任何「重复 / 同构 / 经典题」的判断，都必须给出可核对的最近邻
   （具体比赛或平台 + 题号 + 链接）；查不到就写「待复核」，**禁止编造**。
2. **先解题，再评分**：评任何一维之前，先给出 1–2 条可行解法路线（算法 + 关键步骤 + 复杂度），
   分数必须与路线自洽。
3. **不确定就标注**：每个维度给置信度 high / medium / low，并列出所依赖的假设
   （题面是否完整、数据范围是否齐全等）；题面缺数据范围/样例时先指出缺什么，不脑补。

## 输出

单题输出一张**评分卡**：

```text
【题目】编号 / 标题 / 来源（比赛·年份·题号 / 平台）
【一句话定位】这题真正考什么
【指纹】解法路径 | 关键转化 | 数据结构 | 约束形态
【查重】候选同构题（题号 + 链接 + 同构度 + 差异点）→ D1 结论
【可行解法路线】路线 1：…（算法 + 关键步骤 + 复杂度）；路线 2：…
【评分卡】D1=..  D2=..（R=.. C=.. A=.. T=..）  D3=..
【依据】每个维度过 1–2 句，引用题面中的具体句子、数据范围或样例
【误判风险】最容易踩的坑 / 最容易被误评的地方
【结论】保留 / 改造 / 淘汰 + 一句话理由 + 具体改造建议（若为改造）
【置信度】high / medium / low，以及所依赖的假设
```

批量审核时先做**校准锚点**（挑 1–2 道双方都认为典型的题对齐分数），再出
「题目 × D1/D2/D3/结论」汇总表并落盘；表按 D2 一位小数排序。

结论要与「教学复用价值」联立，不能只凭 D1 高低：

| D1 | 教学复用价值 | 结论 |
|---|---|---|
| 高（4–5） | 高 | 保留，标为巩固/模板题，不进「新题」池 |
| 高（4–5） | 低 | 淘汰或替换 |
| 中（2–3） | 任意 | 视 D2/D3 决定分到哪一层 |
| 低（0–1） | 任意 | 保留为候选新题，重点看 D2/D3 是否够深 |

## 安装

**前置条件**：DeepSeek Harness 桌面版（`desktop` profile）、Node ≥ 22。

本预设**不带 `skills/` 目录**——persona 直接写在 `cordis.patch.yml` 里，所以不需要
`set-skill-dir.mjs` 那一步，也无需额外的技能加载配置。

```text
# 1) 克隆仓库（仓库地址以你 fork/克隆的为准）
git clone <你的仓库地址> dsh-problem-review-preset
cd dsh-problem-review-preset

# 2) 安装 bundle
plugin_manager action=install_bundle target="<克隆后的仓库绝对路径>"
```

安装后**新建会话**，在 Agent 预设列表选择「命题质量审核员」。已开着的会话不会切换。

卸载：`plugin_manager action=remove_bundle target="dsh-problem-review-preset"`，
或从 profile 的 `package.json` 的 `dsh.profile.bundles` 里移除后执行 `pnpm install`。

## 使用

单题：

```text
审这题，用途是新题发布，目标学段 CSP-S：
<贴题面：题目标题、输入输出、数据范围、样例>
```

批量：

```text
这批 20 道题（附件/链接），用途是分层作业题库，先做集合内查重，再出 D1/D2/D3 汇总表。
```

补充说明：

- **先说用途**：新题发布 / 训练题单 / 分层作业 / 题库查重，结论口径不同；
  不说也可，但 Agent 会先假设并写明。
- **只想要结论**：可以说「只给评分卡和结论，不写完整参考代码」——默认就不写完整代码，
  只给算法路线与关键实现要点。
- **改口径**：直接说「D2 权重改成 R 0.4 / C 0.2 / A 0.2 / T 0.2」，或让它按你的考纲重设锚点。

## 改口径（改这个仓库）

`cordis.patch.yml` 里 `persona.prefix` 就是完整的评分准则，调权重、加锚点、换输出格式都在这一处改：

1. 编辑 `cordis.patch.yml`（YAML 块标量，**缩进两空格**，不要把 `prefix: |` 下的缩进改掉）。
2. 重新安装一次让改动生效：
   `plugin_manager action=install_bundle target="<仓库绝对路径>"`。
3. 已开着的会话保留旧版本；**新建**会话才用新版本。

也可以直接在 DSH GUI 的预设编辑器里改（会写进 profile 的 `cordis.patch.yml` 覆盖层）。

## 目录结构

```text
dsh-problem-review-preset/
├── package.json         # bundle 元数据（dsh.bundle.patch 指向 cordis.patch.yml）
├── cordis.patch.yml     # preset 声明；persona.prefix 是完整评分准则
└── README.md
```

`persona` 是常驻系统提示，包含：三条铁律、审核前问清用途、D1/D2/D3 完整口径与锚点、
计分归属规则、输出格式模板、工作方式。全部集中在一个 YAML 块标量里，便于 review 与 diff。

## 依赖与兼容性

- **DSH**：桌面版（`desktop` profile），随包工具 `plugin_manager`。
- **Node**：≥ 22（已在 Node 22.19 上验证）。
- **平台**：已在 Windows 11 上验证；persona 只是提示词，跨平台行为一致。
- **外部依赖**：无。查重如果需要联网检索同构题，会调用会话里可用的 web 搜索工具；
  没有该工具时会降级为「按已有知识判断 + 标注待复核」。

## 已知限制

1. **查重依赖可检索的证据**：题面不完整、或平台上检索不到时，只能给「待复核」而不是确定结论；
   D1 的分数会带置信度，低置信度不要单独作为淘汰依据。
2. **D2 是加权合成分**：不同审核人给的 R/C/A/T 各有主观区间，批量审核前务必先做校准锚点，
   否则多人/多轮结果不可比。
3. **不判题目正确性**：本预设评的是「质量与难度」，不负责验证题面数据是否自洽、样例是否有错；
   发现矛盾会指出，但不替代出题人修订。
4. **不写完整参考代码**：默认只给算法路线与复杂度（需要时可明确要求）。
5. **难度档位是相对估计**，不是等距量表；跨学段比较（如 CSP-J 与 NOIP）要先对齐考纲。
